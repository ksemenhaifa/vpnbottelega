## Четыре проблемы

**1. Четыре сайта пишут в один счётчик.** `veliora.clinic`, `3dlab.co.il`,
`yallapro.co.il` и `web1.co.il` отправляют данные в `G-72QJ6FFJ6N`. Клиника,
стоматлаборатория и студия разработки лежат в одном отчёте вперемешку.
Любая цифра, взятая оттуда без фильтра, неверна.

**2. На трёх сайтах обращения не считаются вообще.** На `gruzhaifa.co.il`
пять ссылок WhatsApp, пять Telegram и пять телефонов — при клике **не уходит
ни одного события**, хотя GA4 и GTM стоят. На `aqualit63.ru` и `tonyateddy.art`
нет GA4, только Метрика, и клики по контактам тоже не отслеживаются.

**3. События называются по-разному.** Где-то `whatsapp_click`, где-то только
автоматический `click`, где-то ничего. Сравнить сайты между собой невозможно —
нет общего знаменателя.

**4. Считается только WhatsApp.** Telegram, телефон и почта не отслеживаются
нигде. При этом на `gruzhaifa.co.il` телефонов на странице столько же, сколько
WhatsApp, а на `tonyateddy.art` основной контакт — вообще Telegram.

## План: три шага

### Шаг 1. Разделить счётчики

Для каждого сайта — **свой ресурс GA4**. Это нужно потому, что сайты принадлежат
разным бизнесам: общие отчёты, аудитории и конверсии у них не совпадают.

В GA4: Администратор → Создать ресурс → внутри него Потоки данных → Веб →
указать домен. Получите новый `G-XXXXXXXXXX` — его и ставьте на сайт вместо общего.

| Сайт | Что сделать |
|---|---|
| veliora.clinic | новый ресурс |
| 3dlab.co.il | новый ресурс |
| yallapro.co.il | новый ресурс |
| web1.co.il | оставить `G-72QJ6FFJ6N` за собой |
| gruzhaifa.co.il | уже отдельный — ничего не менять |
| aqualit63.ru | новый ресурс (сейчас GA4 нет) |
| tonyateddy.art | новый ресурс (сейчас GA4 нет) |
| kotel63.ru | сначала разобраться, почему сайт не открывается |

> **Старые данные не переносятся.** Ресурс GA4 начинает собирать статистику
> с момента создания. История из общего счётчика останется там — не удаляйте его.

**Пока счётчики не разделены** скрипт `contact-tracker.js` добавляет к каждому
событию параметр `site`. По нему общий счётчик уже можно фильтровать, и цифры
будут верными до перехода на отдельные ресурсы.

### Шаг 2. Поставить общий трекер

Файл `contact-tracker.js` из этого репозитория — один и тот же на все сайты.
Он даёт одинаковые события везде:

| Событие | Когда |
|---|---|
| `whatsapp_click` | клик по любой ссылке WhatsApp |
| `telegram_click` | клик по Telegram |
| `phone_click` | клик по номеру телефона |
| `email_click` | клик по почте |
| `lead_form_submit` | отправка формы |

Параметры каждого события:

| Параметр | Что показывает |
|---|---|
| `site` | какой сайт (пока счётчик общий — главный параметр) |
| `page_path` | с какой страницы написали |
| `section` | из какого блока: «Лазерная эпиляция», «Цены», «Футер» |
| `destination` | на какой номер или адрес ушли |
| `link_text` | что было написано на кнопке |
| `traffic_source` | откуда пришёл человек: поиск Яндекс, Instagram, utm-метка |
| `visitor_id` | короткий номер посетителя — сверять с перепиской |

Установка: перед `</body>`, **после** кода счётчика.

```html
<script>window.CT = { site: 'veliora.clinic' };</script>
<script src="/contact-tracker.js" defer></script>
```

На `3dlab.co.il` и `yallapro.co.il` своё событие `whatsapp_click` уже есть —
чтобы не задвоить, добавьте `skipWhatsApp: true`:

```html
<script>window.CT = { site: '3dlab.co.il', skipWhatsApp: true };</script>
```

Если Метрика на сайте есть, события уходят и туда — отдельной настройки не нужно.

### Шаг 3. Отметить конверсии и продлить хранение

В каждом ресурсе GA4:

1. **Администратор → События → Отметить как ключевое событие** для
   `whatsapp_click`, `telegram_click`, `phone_click`, `lead_form_submit`.
   После этого обращения видны в обычных отчётах, а не только в Исследованиях.
2. **Администратор → Настройки данных → Хранение данных → 14 месяцев.**
   По умолчанию стоит 2 месяца, и данные для Исследований удаляются.
   Это ровно та причина, по которой нельзя посмотреть статистику за прошлый квартал.
3. **Администратор → Специальные определения** → добавить параметры
   `site`, `section`, `destination`, `traffic_source` как специальные параметры
   уровня события. Без этого они не появятся в отчётах как измерения.

> Пункт 3 обязателен: GA4 принимает любые параметры, но показывает в отчётах
> только те, что зарегистрированы вручную. Регистрируйте до того, как пойдут
> данные — задним числом параметры не подтягиваются.

## Отчёт, который отвечает на вопрос «что дал сайт»

GA4 → Исследования → Пустое исследование:

- **Параметры:** `site`, `page_path`, `section`, `traffic_source`
- **Показатели:** `Количество событий`, `Активные пользователи`
- **Фильтр:** `Название события` — один из `whatsapp_click`, `telegram_click`, `phone_click`
- **Строки:** `site` → `page_path` → `section`

Получится таблица «сайт → страница → блок → сколько обращений», с разбивкой
по источнику трафика. Это и есть ответ заказчику, сколько людей написали
с сайта и откуда они пришли.

## Что проверить после установки

На каждом сайте: открыть страницу, нажать кнопку WhatsApp, открыть
GA4 → Отчёты → **В реальном времени**. Событие `whatsapp_click` должно
появиться за минуту. Не появилось — значит скрипт не подключился: проверьте,
что тег стоит после счётчика и что файл отдаётся (открыть его адрес напрямую).

Для отладки включите логи:

```html
<script>window.CT = { site: 'veliora.clinic', debug: true };</script>
```

В консоли браузера будет видно каждое отправленное событие со всеми параметрами.
