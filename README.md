# Стрижи · Водоснабжение — интерактивная схема сети

Модуль для сайта (или отдельная страница) с анимированной схемой водоснабжения посёлка:
три скважины, две магистрали (ул. Сиреневая и ул. Вишнёвая), ответвления к домовладениям.
Схема считает давление в каждой точке сети, показывает направление и скорость потока,
принимает показания манометров от жителей и подсвечивает, где давление проседает,
где завышено и где показания расходятся с расчётом (порыв, засор, прикрытая задвижка,
проблема на вводе дома).

Без сборки и зависимостей: чистые HTML/CSS/JS.

## Быстрый старт

```bash
node server/server.mjs          # http://localhost:8080 — страница + общий журнал показаний
```

или просто откройте `dist/strizhi-water.html` в браузере (автономный файл, показания
хранятся в браузере пользователя).

## Что умеет

| Блок | Описание |
|---|---|
| **Схема** | SVG с панорамированием и масштабом. Трубы — толщина по диаметру, бегущие штрихи — направление и скорость воды. Три раскраски: *Давление* (красное — проседает, синее — завышено относительно нормы), *Отклонение* (показание жителя − расчёт), *Поток* (скорость в трубе). |
| **Часы суток** | Ползунок и «проигрывание» суток: водоразбор меняется по суточному профилю, давление пересчитывается на лету. |
| **Показание** | Житель вводит адрес и давление по манометру. Модуль сравнивает с расчётом на момент замера и помечает дом: норма / заметное / сильное отклонение. |
| **Журнал** | Все показания с расчётом и Δ; устаревшие (старше `readingTtlHours`) не участвуют в диагностике. |
| **Сценарий** | Давление и включение каждой скважины, множитель потребления (полив), перемычки/задвижки, имитация порыва в любой точке магистрали. |
| **Диагностика** | Текстовые выводы: перекос по улицам, дома ниже/выше нормы, высокие скорости, кластеры отклонений (соседние дома с низким показанием → проблема на магистрали; одиночный дом → проблема на вводе). |
| **Профиль давления** | График давления вдоль каждой магистрали с нормативной полосой и точками показаний. |

## Гидравлика

`assets/js/hydraulics.js` — установившийся режим, потери напора по Хазену-Вильямсу
(`h = 10.67·L·Q^1.852 / (C^1.852·D^4.87)`), узловые балансы решаются методом линеаризации
сопротивлений, поэтому корректно считаются кольца и несколько источников. Учтены:
характеристика насоса (напор падает с расходом, `curveK`), обратные клапаны скважин
(если напор сети выше напора скважины, она не подаёт воду), отметки земли, суточный
профиль водоразбора. Расчёт ~5–30 мс для 140 узлов.

## Адаптация под реальный посёлок

Вся геометрия — в `assets/js/config.js` (`SW.defaultConfig`):

* `wells` — координаты (м), отметка `z`, давление на выходе, к какому узлу подключена, труба.
* `streets` — ось магистрали, шаг узлов, диаметр/материал магистрали и вводов, отметки в начале
  и в конце, пустые участки (`skipSlots`). Нумерация домов: нечётные — верхняя сторона, чётные — нижняя.
* `links` — перемычки между улицами, с задвижкой или без.
* `norm`, `deviation`, `readingTtlHours`, `hourProfile`, `houseDemand` — нормативы и режим потребления.
* `background` — растровая подложка (план посёлка) с привязкой в метрах: удобно расставлять
  дома прямо по генплану.

Если удобнее описывать сеть не «улицами», а списком узлов и труб — `SW.buildNetwork` возвращает
обычный граф (`nodes`, `pipes`), его можно собирать любым способом.

## Встраивание в существующий сайт

```html
<link rel="stylesheet" href="assets/css/scheme.css">
<div id="water-scheme"></div>
<script src="assets/js/config.js"></script>
<script src="assets/js/hydraulics.js"></script>
<script src="assets/js/reports.js"></script>
<script src="assets/js/scheme.js"></script>
<script src="assets/js/profile.js"></script>
<script src="assets/js/app.js"></script>
<script>
  SW.mount(document.getElementById('water-scheme'), {
    apiUrl: '/api/readings',   // общий журнал показаний; уберите — будет localStorage
    // config: myConfig,       // своя конфигурация сети
    // seedDemo: false,        // не загружать демо-показания при первом открытии
  });
</script>
```

Автономный вариант одним файлом: `node tools/build-single.mjs` → `dist/strizhi-water.html`
(`--fragment` — без `<html>/<head>/<body>`, для вставки в CMS).

## Сервер показаний

`server/server.mjs` — Node ≥ 18, без зависимостей. Раздаёт статику и хранит показания в
`server/data/readings.json`:

* `GET  /api/readings` — список
* `POST /api/readings` — `{ houseId, address, pressure, comment }`
* `DELETE /api/readings/:id`

Для другого бэкенда (PHP, Python) достаточно повторить эти три метода — фронтенд ждёт JSON
такого же вида. При недоступности API модуль продолжает работать на локальной копии.

```
assets/js/app.js           интерфейс, диагностика, SW.mount()
server/server.mjs          статика + API показаний
tools/build-single.mjs     сборка автономного HTML
dist/                      собранные файлы
```
