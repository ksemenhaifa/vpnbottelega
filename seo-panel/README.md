# SEO-панель

Рабочая панель под паролем: показывает по каждому сайту данные Google Search Console,
Google Analytics, Яндекс Вебмастера и Яндекс Метрики, частотность запросов из Wordstat
и сама проверяет сайт на то, что мешает индексации.

## Что умеет

- **Вход по паролю.** Пароль хранится только в виде хэша (scrypt); после 5 неверных
  попыток адрес блокируется на 15 минут.
- **Подключение Google и Яндекса кнопкой** на странице «Подключения» (OAuth, доступ только
  на чтение). Сайты подтягиваются сами и сопоставляются по домену.
- **Сводка по сайтам:** клики, показы, позиция, сессии, визиты, ИКС, страниц в поиске —
  за 28 дней с изменением к предыдущим 28 дням.
- **Список проблем с приоритетом** («Срочно / Важно / Желательно») по каждому сайту.
- **Собственная проверка сайта**, которой не нужны никакие ключи: robots.txt, главная
  страница и выборка адресов из sitemap — какие из них с `noindex`, с редиректом, отдают 404,
  закрыты в robots.txt или имеют canonical на другой адрес. Это те самые причины, о которых
  пишет Search Console, но с конкретными адресами.
- **Проверка индексации в Google** для главной и для страниц, которые вы отметили
  как отслеживаемые.
- **Ключевые слова:** частотность фраз и связанные запросы из Wordstat.
- Данные обновляются сами раз в 6 часов и по кнопке «Обновить данные».

## Что проверено, а что нет

Проверено автотестами и вручную в браузере (на подставных данных, без настоящих аккаунтов):
вход и ограничение попыток, защита форм, подключение/отключение источников, сбор и показ
данных, проверка сайта, вёрстка на компьютере и телефоне, светлая и тёмная тема.

**Не проверено на настоящих API.** Запросы к Google и Яндексу написаны по их документации,
но сверить их с живыми сервисами при разработке было нельзя. Наименее надёжная часть —
Wordstat: это новое API, доступ к нему Яндекс выдаёт по заявке. Если какой-то запрос
окажется не в том формате, панель покажет текст ошибки от сервиса на странице «Подключения»
или на странице сайта, а не подставит неверные цифры. Первое подключение — это и есть
проверка; по тексту ошибки запрос правится быстро.

## Установка на сервер

Нужны Python 3.10+ и nginx с HTTPS. Пути, пользователь и порт ниже — пример.

```bash
sudo useradd --system --home /opt/seo-panel seo-panel
sudo mkdir -p /opt/seo-panel /var/lib/seo-panel
sudo cp -r app requirements.txt /opt/seo-panel/
sudo python3 -m venv /opt/seo-panel/.venv
sudo /opt/seo-panel/.venv/bin/pip install -r /opt/seo-panel/requirements.txt
sudo chown -R seo-panel: /var/lib/seo-panel && sudo chmod 700 /var/lib/seo-panel
```

1. Скопируйте `.env.example` в `/etc/seo-panel.env` (права `600`), заполните. Хэш пароля:
   `cd /opt/seo-panel && .venv/bin/python -m app.hashpw`.
2. Установите `deploy/seo-panel.service` в `/etc/systemd/system/`, затем
   `sudo systemctl enable --now seo-panel`.
3. Добавьте блок из `deploy/nginx-location.conf` в HTTPS-сервер nginx и перезагрузите nginx.
4. Откройте адрес из `PANEL_BASE_URL`, войдите, перейдите в «Подключения».

Без заполненных `PANEL_SECRET_KEY`, `PANEL_PASSWORD_HASH` и `PANEL_BASE_URL` служба не
запустится — это сделано намеренно.

Служба слушает только `127.0.0.1`, наружу её отдаёт nginx. В простое занимает около 75 МБ
памяти; в unit-файле стоит ограничение 300 МБ.

## Подключение источников

Страница «Подключения» показывает точные шаги и нужный Redirect URI. Коротко:

- **Google:** в Google Cloud Console включить Search Console API, Google Analytics Data API
  и Google Analytics Admin API, создать OAuth client ID типа «Web application».
- **Яндекс:** на oauth.yandex.ru создать приложение с правами на чтение Вебмастера и Метрики.
- **Wordstat:** подать заявку на доступ к API Вордстата для этого же приложения
  (или задать отдельный `WORDSTAT_TOKEN`).

Client ID и секреты записываются только в `/etc/seo-panel.env` на сервере.

## Безопасность

- Токены доступа лежат в `panel.sqlite3` в каталоге данных (права `600`), не шифруются.
  Доступ у них только на чтение статистики. Резервные копии этого файла храните как секрет.
- Панель сама ходит по адресам из sitemap, поэтому отказывается обращаться к внутренним
  адресам сети.
- Панель закрыта от индексации (`X-Robots-Tag: noindex`).

## Посмотреть локально на подставных данных

```bash
python3 -m venv .venv && .venv/bin/pip install -r requirements-dev.txt
.venv/bin/python -m tests.preview     # http://127.0.0.1:8765/panel/  пароль: correct horse battery
.venv/bin/python -m pytest            # тесты
```

Все цифры в этом режиме выдуманы (`tests/fakes.py`).
